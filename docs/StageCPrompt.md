# Поручение: реализовать только этап C — Chrome

Проект `/Users/stubbs221/Zapas`, GitHub `Stubbs221/Zapas`, ветка `main`. Прочитай `AGENTS.md`, `README.md`, `docs/ProjectPlan.md`, `docs/StageA.md`, `docs/StageARunbook.md`, `docs/StageAReport.md`, `docs/StageBReport.md` и `docs/CLI.md`. Сохрани существующие изменения и контракт JSON v1.

Реализуй только C: production-расширение Chrome, установку Native Messaging, lifecycle локального GUI-сервиса/Unix socket, вкладки и исключения, ручной выбор объектов, выборочную выгрузку и отдельное закрытие, повторную проверку результата. GUI остаётся самостоятельным без расширения. Продолжи архитектуру Swift 6/macOS 14+, ZapasCore и единственного SamplingCoordinator; не создавай второй постоянный монитор при CLI-вызове рядом с GUI. База B: нативная русская MenuBarExtra-оболочка, bounded in-memory история и read-only `zapas status/processes --json`. Протокол probe A экспериментальный и не заменяет публичный JSON v1.

До зависимых сценариев проверь ограничения и PASS/FAIL/NOT RUN в отчёте B. Устрани либо явно согласуй открытые критерии приёмки B; не выдавай реализацию за полную квалификацию. Независимые контракт, установка, reconnect и UI могут разрабатываться при непроведённых macOS 14/sleep-wake/LLDB/Charles-проверках, но эти результаты не становятся PASS. Реальные login/relogin, полный VoiceOver, MenuBarExtra и latency требуют отдельной фактической проверки. LLDB отложен пользователем; Charles не квалифицирован.

Используй выбранный fallback: давность активности и наблюдаемый footprint группы Chrome. Точная RAM вкладок неизвестна; не ранжируй её выдуманными числами. RSS и footprint раздельны, сумма footprint не является уникальной физической RAM. Проверяй session/profile identity, допустимый extension ID и origin, версии/request ID, reconnect после перезапуска service worker, несколько профилей/окон, замену tab ID и исчезновение объектов. Не сохраняй полный URL, содержимое формы или приватный трафик в обычной диагностике.

Действия только над явно выбранными пользователем вкладками, с preview и свежей повторной проверкой перед исполнением. Выгрузка и закрытие — разные действия; закрытие не подменяет discard. Защити active/pinned/audible/incognito, неизвестную/свежую активность и пользовательские исключения; состояние confirmed/failed/unknown определяется реальным результатом, не отправкой команды. Порог 60 с из фикстур A не является утверждённой production-политикой: согласуй недостающие продуктовые пороги перед зависимым исполнением. Установка и разрешения интеграции — явный понятный шаг; не меняй рабочий Chrome-профиль и не подключай расширение скрытно.

Проверки действий выполняй только в специально созданном изолированном Chrome-профиле на собственных тестовых страницах; не трогай рабочие вкладки.
