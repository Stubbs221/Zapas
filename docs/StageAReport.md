# Отчёт этапа A — Zapas

Дата проверки: **01.10.2026**, arm64. Технические прототипы реализованы, собираются и проходят описанные ниже проверки. Полная квалификация на минимальной ОС и часть ручных сценариев ещё не завершены. Живая проверка LLDB отложена по явному выбору пользователя. Это отчёт о текущем коде; исторические цифры импортированного плана не используются как результаты продукта.

## Метрики и стоимость

Текущая машина: **36 GiB physical RAM**, размер страницы **16 KiB**, swap used/total и наблюдаемые swap deltas — 0 на базовом снимке. Это наблюдение, не обещание отсутствия swap при нагрузке. В sandbox агента sysctl swapusage/boottime были запрещены: swap и скорости корректно стали недоступны; обычный запуск от текущего пользователя вне этого sandbox получил значения. Root и Full Disk Access не требовались для полученных значений. Доступ ко всем чужим/системным процессам не гарантируется.

Размер страницы совпал с vm_stat; физический размер компрессора совпал в последовательных снимках. Wired отличался на **2,002%**. Для пяти одинаковых живых PID сравнение footprint с округлённым `top MEM`: четыре расхождения **0,035–0,123%**, одно **6,715%** в работающем процессе. Временной дрейф и округление сохраняются; это не доказательство точности до процента под любой нагрузкой. Activity Monitor подтвердил physical RAM 36 GiB и swap 0; выбранный процесс в его снимке уже исчез, поэтому процессное UI-сравнение не объявляется успешным.

Footprint и RSS возвращаются отдельно через `proc_pid_rusage`; идентичность и UID повторно читаются после памяти. Исчезновение, PID reuse и отказ API имеют явные ошибки. Все метрики имеют timestamp, units и source. `chrome-memory` считает footprint только наблюдаемых путей внутри `Google Chrome.app`, отмечает отсутствующие измерения и не классифицированные ошибки. На одном снимке прочитано 26 таких процессов, сумма около 1,65 GiB. Это сумма учёта наблюдаемых процессов: разделяемые страницы, динамическое дерево процессов и пропуски запрещают называть её уникальной физической RAM. RSS к ней не прибавляется. Классификация по пути не заменяет подпись/bundle identity для будущих действий.

Короткий benchmark debug-сборки, 30 итераций:

| Операция | Медиана | Максимум |
| --- | ---: | ---: |
| SystemMonitor | 0,0193 мс | 0,0593 мс |
| ProcessInventory текущего пользователя | 4,725 мс | 5,611 мс |

Footprint самого probe — 3 916 280 байт (~3,735 MiB), RSS — 8 552 448 байт; CPU за benchmark — 0,141337 с. Это разовый короткий executable без UI, не доказательство бюджетов GUI <100 MB, <1% фонового CPU или запуска <200 мс. Измерения повторять после появления оболочки B.

## Chrome: решение для MVP

[Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs) даёт вкладки, состояние и lastAccessed, но не достоверную вкладочную RAM; [Processes API](https://developer.chrome.com/docs/extensions/reference/api/processes) документирован для Dev channel. Надёжный источник точной памяти вкладки Stable не установлен. Принят альтернативный MVP: **давность активности + наблюдаемый общий footprint Chrome**, вкладочная память неизвестна. CDP использовался только для opt-in теста, без сетевого порта; продукт и измерение вкладочной памяти на него не опираются. Accessibility-считывание task manager не реализовано.

Живой тест подтвердил загрузку unpacked в Stable, Native Messaging roundtrip, защиту pinned/active/recent/audible, active tabs в двух окнах, выбранный fixture discard, восстановление при фокусировке соответствующего окна, пересоздание JavaScript heap, отключение и новую host identity при reconnect. Chrome заменил tab ID при discard: код сверяет окно/nonce новой вкладки и передаёт ownership только после проверки. После восстановления Chrome вернул текст тестового поля; это **не** гарантия сохранности произвольного состояния страницы.

После отправленного API-вызова отсутствие подтверждения — `unknown`, а не отказ «ничего не произошло». Перед вызовом заново проверяются nonce, навигация, окно, lastAccessed и исключения. Только extension-created fixtures могут быть целью. Пауза 60 секунд — исследовательский порог, не утверждённая политика продукта. JSON v1 остаётся экспериментальным.

Incognito запрещён manifest и проверен unit-тестом; живой incognito — NOT RUN. Реальное выключение расширения и принудительная остановка worker — NOT RUN (ручной disconnect/reconnect проверен). Старые fixtures после потери worker ownership нельзя выгружать; политика отказывает. Несколько host-сессий проверены интеграционно; несколько одновременно подключённых живых Chrome-профилей — NOT RUN. Стоимость/эффект выгрузки в RAM не измерялись: такое сравнение относится к E.

## Simulator, LLDB и Charles

Создано отдельное устройство **Zapas Stage A**, iPhone 18 Pro / iOS 27.0, после повторного чтения всех runtimes. Всего 7 ≤8. Оно не загружалось; установки, запусков, Simulator screenshots и логов не было. Видимый запуск приложения не утверждается. UDID и назначение остаются локальными. Нельзя брать generic Booted другого проекта. Код умеет сопоставить executable только внутри конкретного device dataPath; generic Simulator/app/helper или отсутствующий путь дают неизвестную принадлежность. Команда `simulators --processes` проверена живым чтением: при выключенном выделенном устройстве наблюдаемые процессы явно получили `unknown`. Полное живое дерево процессов запущенного устройства пока не квалифицировано.

LLDB-прототип только читает libproc, UID/PPID и start identity. PPID=1 означает `orphan_candidate_activity_unknown`, а не разрешение завершить процесс. Отложенную живую проверку выполняет пользователь через Xcode по runbook; автоматического завершения отладчика нет.

По [документации Charles](https://www.charlesproxy.com/documentation/using-charles/web-interface/) доступны управление recording и экспорт/скачивание сессии. Реальное сохранение, повторное открытие и новая сессия **требуют проверки**. В этап A не добавлены control commands, изменение proxy/SSL или чтение рабочего трафика.

## Зафиксированная архитектура этапа B

1. Нативная SwiftUI/AppKit оболочка, MenuBarExtra `.window`; при подтверждённых проблемах — NSStatusItem + NSPopover. Русские тексты, компактные карточки по локальному референсу [OpenUsage](https://www.openusage.ai/), светлая/тёмная тема, доступность. Ширина около 420 pt как старт для проверки плотности, ограниченная высота со скроллом.
2. Независимый от UI ZapasCore; единственный coordinator/actor владеет sampling state. libproc и simctl не выполнять на main actor; по умолчанию без main-actor isolation в shared core. Отсутствие Chrome/Xcode не мешает системной карточке и списку приложений. В B интеграции отображаются как отсутствующие/отложенные, без кнопок действия.
3. Подробные метрики при открытом окне примерно 2–3 с, лёгкие системные в фоне 15–30 с; это начальные настройки, измерить стоимость. Pressure observer живёт с coordinator; initial unknown. Сброс baseline по sleep/wake notifications плюс проверки boot/page/time; нельзя полагаться только на эвристику короткого сна.
4. Ограниченный локальный кольцевой буфер и график последних 15 минут; никаких загрузок диагностики наружу. На B сначала history в памяти. Не хранить сырой inventory/URL по умолчанию. Ошибки, stale и unknown — отдельные состояния.
5. Публичный read-only CLI JSON v1 спроектировать и документировать в B; не заморозить автоматически экспериментальный probe JSON. Одна схема метрик/источников с приложением, отдельно определить единицы, ошибки, коды выхода и сроки хранения. IPC/socket prototype проверен, но production lifecycle и установка Native Messaging остаются C; не добавлять второй постоянный монитор ради прототипа.
6. Login item через настройку пользователя, по умолчанию выключен. Локальная сборка/упаковка .app и проверка видимого menu bar UI на текущей macOS; signing/distribution отдельно документировать. Нет kill/shutdown/browser restart/Charles control, GUI automation команд и MCP.

Оболочку B можно разрабатывать независимо от отложенного LLDB и Charles. Полную квалификацию минимальной macOS, sleep/wake, UI-сравнения процессов и жизненного цикла интеграций продолжать с явным статусом; не переносить NOT RUN в PASS. Следующий этап автоматически не начат.
