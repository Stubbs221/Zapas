# Этап A — техническая проверка Zapas

Утверждённый результат: библиотека `ZapasCore`, executable `zapas-probe`, расширение Manifest V3, Native Messaging host, прототип локального IPC, тесты и отчёт с проверенными ограничениями. GUI, MCP и автоматические действия не входят в этап.

## Метрики

Использовать системные API macOS для physical/wired/compressed memory, swap и разностей swapin/swapout. Сохранять размер страницы, время, источник и единицы. Первый интервал, сброс счётчиков, перезагрузка и сон/пробуждение не дают достоверной скорости. Процессы: libproc, footprint и RSS раздельно; PID + время старта, UID, PPID. Недоступность и исчезновение процесса возвращать явно.

Сверять с Activity Monitor, vm_stat и top. Учёт разделяемых страниц не позволяет трактовать сумму footprint как уникальную RAM. Измерить стоимость самого прототипа; бюджеты GUI из плана пока не проверяются.

## Chrome и IPC

Отдельный Chrome Stable user-data-dir в `.local/`, без синхронизации. Расширение запрашивает только `tabs` и `nativeMessaging`. Native Messaging проверяет origin, версию, request ID и размеры сообщений. IPC — Unix domain socket в каталоге текущего пользователя с приватными правами; проверить UID peer, фрейминг, разрыв и несколько подключений. Не открывать HTTP-сервер команд или remote debugging для обычного сбора метрик.

После просьбы пользователя выполнить установку и проверку самостоятельно добавлен отдельный opt-in test harness: `tools/test_chrome.py --run`. Он запускает Chrome Stable с приватным `--remote-debugging-pipe` и `--enable-unsafe-extension-debugging`, загружает только расширение из репозитория и закрывает собственный тестовый процесс. Сетевого debug-порта нет. Это способ автоматизации тестов, не зависимость продукта и не источник памяти вкладок. Рабочий профиль не используется. Обычный ручной запуск обходится без этих флагов.

В этапе A выгружать только тестовые страницы, созданные самим расширением, после явного выбора ID. Не принимать URL/названия за команды. Повторно проверять активность каждого окна, закрепление, аудио, инкогнито, недавнюю активность и навигацию. Отказ и исчезновение вкладки — отдельные результаты. Прототип JSON экспериментальный; контракт публичного CLI оформляется на этапе B.

Точная RAM вкладок Chrome Stable — исследуемая возможность. Если надёжного API нет, принять давность активности и общий расход Chrome; неизвестную вкладочную память не заменять нулём. Проверить несколько окон и подключений, восстановление по активации, отключённое расширение и перезапуск service worker.

## Simulator, LLDB и Charles

Читать simctl JSON, выделять iOS, явно показывать unavailable и неизвестную принадлежность процессов. Перед созданием выделенного `Zapas Stage A` прочитать полную инвентаризацию; не превышать восемь устройств. Записывать назначенный UDID только локально. Не использовать чужие устройства, включая generic Booted.

LLDB: записать наблюдения до, во время отладки, после Stop и выхода из тестовой Xcode-сессии. Управление Xcode выполняет пользователь. PPID=1 — лишь кандидат на осиротевший процесс, не доказательство безопасности завершения. Команд завершения LLDB в этом этапе нет.

Charles: проверить документированные экспорт/скачивание сессии через Web Interface и подготовить ручной сценарий. Не включать интерфейс, не менять proxy/SSL, не читать рабочий трафик и не перезапускать Charles автоматически. Реальное сохранение до ручной проверки остаётся неизвестным; управление относится к этапу F.

## Приёмка

- Сборка Swift 6 и тесты Swift Testing проходят на текущей macOS; совместимость с macOS 14 отдельно отметить как проверенную либо NOT RUN.
- Проверены расчёт скоростей, смена page size/boot, сон, сброс счётчиков, PID reuse и исчезновение процесса.
- Проверены исключения вкладок и повторная проверка изменившегося состояния.
- Проверены повреждённые/обрезанные сообщения, несовместимая версия, неверный origin, отключение и несколько IPC-подключений.
- Проверены смешанные runtimes и недоступный Xcode; отсутствие разрешения не считается пустым списком.
- В `StageAReport.md` записаны версии, команды, PASS/FAIL/NOT RUN, стоимость, ограничения, матрица возможностей и архитектура этапа B.

Непроверенные живые сценарии не маркировать PASS. Техническая реализация и квалификация этапа учитываются отдельно.
